# plan.md 契约

路径：`docs/plans/{Work-Item-Key}/plan.md`；已存在时使用下一个可用的 `plan-{n}.md`。

```markdown
# 实施计划

## 文档信息
- Work Item：
- 输入文件：
- 当前计划文件：
- 状态：Pending / In Progress / Blocked / Done
- 创建时间：
- 更新时间：

## 1. 实施目标
## 2. 实施范围
## 3. 不实施范围
## 4. 依赖与执行顺序
## 5. 任务清单

### Task 1：任务名称
- 关联：US-001 / AC-001 / BUG-001
- 状态：Pending
- 负责人：
- 文件：
- RED：测试和预期失败
- GREEN：最小实现和通过条件
- REFACTOR：整理范围和复验
- 验证命令：
- 完成标准：
- 阻塞原因：

## 6. 任务状态总览
| Task | 状态 | 负责人 | 开始时间 | 完成时间 | 阻塞原因 |
## 7. 需求/缺陷到测试映射
## 8. 风险、回滚和人工 Gate
## 9. 项目级文档更新计划
## 10. 执行记录
```

每个任务必须写明具体文件、行为、测试和可观察完成标准；新功能和缺陷修复遵循 RED -> GREEN -> REFACTOR；被新方向替代的任务标为 `Superseded`，不删除历史记录。
