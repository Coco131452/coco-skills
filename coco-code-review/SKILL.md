# Coco 代码审查

以评审姿态工作：先报告问题，按严重程度排序，并用具体文件/行号和可复现路径支持结论。摘要放在问题之后。

## 范围

1. 确认评审基线和目标 diff，避免混入用户其他未提交变更。
2. 读取需求/缺陷分析、设计、计划、变更记录和验收标准。
3. 检查行为正确性、边界和失败处理。
4. 检查契约、数据一致性、Migration、兼容和并发。
5. 检查认证授权、输入处理、密钥、隐私和审计。
6. 检查性能、资源生命周期、可观测性和部署风险。
7. 检查测试是否覆盖新增逻辑、原始缺陷、共享调用方和关键回归。
8. 运行适当的测试或静态检查；无法运行时明确残余风险。

## 严重程度

- **P0 Critical**：数据损坏、严重安全、生产不可用或无法回滚。
- **P1 Major**：核心功能错误、明显回归、权限绕过或高概率事故。
- **P2 Moderate**：边界缺陷、维护风险或测试缺口，会在现实场景触发。
- **P3 Minor**：低风险但具体可执行的改进。

不要把纯风格偏好当问题，不要只根据测试通过推断行为正确。若没有发现问题，明确说“未发现可执行问题”，并列出尚未覆盖的验证范围。

发现 P0/P1 时不得建议交付；修复后重新审查相关 diff 和回归结果。
