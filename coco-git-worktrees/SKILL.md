# Coco Git Worktree

仅在仓库中工作且隔离确有价值时使用。小型只读调查、非 Git 目录或用户要求直接在当前分支修改时不强制创建。

## 创建前

1. 检查仓库根目录、当前分支、工作区状态和已有 worktree。
2. 优先使用项目已约定的 worktree 目录；否则使用仓库外清晰命名的位置。
3. 确认目标目录不包含用户数据，并验证仓库内 worktree 目录已被忽略。
4. 使用工作项 ID 形成分支名，如 `feature/REQ-...` 或 `fix/BUG-...`；已有团队规范优先。

## 创建后

- 验证新 worktree 路径、分支和 HEAD。
- 按项目文件识别依赖安装和基线测试命令，不凭技术栈猜测。
- 基线失败时记录现有失败，避免把它误算为本次回归。
- 不复制 `.env`、密钥或机器凭据；需要时仅说明缺失配置。

## 清理

删除 worktree、分支或目录属于破坏性操作。只在用户明确要求，且已确认变更提交/保存、路径准确、无未跟踪成果时执行。不要使用广泛路径或递归删除替代 `git worktree remove`。

完成后报告 worktree 路径、分支、基线状态和仍需配置的事项。
