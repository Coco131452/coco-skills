# Coco 执行计划

开始前读取 `index.md`、有效分析/设计、`plan.md` 和开放变更；检查当前代码与计划假设是否一致。计划明显过期时不要盲目执行。

## 执行循环

1. 选择依赖已满足的最小垂直切片，将状态改为 `In Progress`。
2. 使用 `coco-tdd` 先建立失败测试或等价的可观察失败证据。
3. 实现最小变更，同时维护公开契约、数据迁移、安全和观测能力。
4. 运行聚焦测试，再运行受影响回归、静态检查和构建。
5. 对用户可见行为使用真实运行环境验证，不能只以 Build 成功代替。
6. 更新任务状态、执行记录、验证证据和代码索引。
7. 在高风险切片、批次结束或交付前运行代码审查。

批次大小由风险和反馈速度决定；高耦合或高风险任务缩小批次。

## 变更与阻塞

- 人工测试发现实现偏差：记录缺陷，修复并补回归测试。
- 用户提出新方向：立即进入 `coco-change-control`；L3/L4 暂停相关任务。
- 只有格式或说明整理可延后到批次结束，指导当前开发的规格必须先更新。
- 无法执行验证时记录 Blocker、最接近的证据和未验证范围，不得标记完全通过。

未经用户要求不提交、推送、创建 PR 或部署。完成计划不等于自动获得这些外部操作权限。
